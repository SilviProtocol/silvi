## Purpose

Determine whether the radiata benchmark failure is a **representation problem** or a **classifier/fusion/head problem**.

If the AE embeddings and model hidden states at the canonical benchmark look like plantation/conifer training points, then the model has the right representation but fails to convert it into the correct ranking — the fix is in the loss/head/fusion.

If they look like native broadleaf training points, then the representation itself doesn't contain plantation signal — no classifier fix will help, and the bottleneck is data scope.

## Method

1. Cached the canonical benchmark feature vector from a single GEE sampling session
   - Coordinate: (-41.151583464812404, 175.09968969862783) — Wairarapa, NZ
   - Year: 2023
   - Saved to `orchestrator/v43c_benchmark_cache.npz` (deterministic, reusable)

2. Scanned all 12 V4.1 training shards (11,920,314 rows) and computed cosine similarity between the benchmark and every training point in three spaces:
   - **AE primary** (64D): raw satellite appearance embedding (`emb_00`..`emb_63`)
   - **AE temporal** (512D): 8-year satellite change sequence (`ae_2017_00`..`ae_2024_63`)
   - **Pre-logit hidden** (384D): model's internal representation after all fusion/gating/residual blocks, before the species output head

3. Kept the top-200 nearest neighbors in each space, classified each by taxonomy

4. Compared neighbor composition against model logit ranking at the same point

## Diagnosis

**The representation does NOT contain plantation signal at this benchmark.**

The AlphaEarth embeddings at (-41.15, 175.10) look like NZ native temperate broadleaf forest. In all three representation spaces — raw satellite, temporal sequence, and trained hidden state — the nearest neighbors are overwhelmingly NZ native broadleaf angiosperms. Not a single Pinaceae training point is among the 200 closest in any space.

This means:
- The classifier IS faithfully reflecting the representation. The logit ranking (broadleaf-heavy) matches the neighbor composition (broadleaf-heavy).
- The model is not "failing to use" plantation signal. There is no plantation signal to use.
- Adjusting the loss function, class weighting, background sampling, or fusion architecture cannot fix a problem that exists in the input representation.

## Why This Happens

The V4.1 training data has only 706 Pinus radiata rows, of which 7 are within 25km of the benchmark. These 7 points are lost among thousands of NZ broadleaf observations at nearby coordinates with similar AE signatures.

The AE embeddings encode land cover **appearance**, not species identity. A Pinus radiata plantation and native broadleaf forest at the same latitude/climate may have substantially different satellite appearance — but with only 7 local training points, the model never learns to distinguish the benchmark's AE pattern as "radiata-like."

The old V3 training data had 9,616 radiata rows (8,705 from backfill), including 39 within 25km. That's 5.6x more local support. The backfill extraction currently running (66% complete) will restore this support.

## Decision

Per Codex's decision framework:

> "If AE / hidden neighbors are not plantation/radiata-like, then data scope / feature representation is the bottleneck."

**Next step: V4.3a (backfill merge), not V4.4 (background negatives).**

V4.4 true background negatives cannot teach the model "this location is a plantation" when the nearest training points in every representation space are native broadleaf trees. Background negatives help with spatial specificity (where species DON'T grow), not with recognizing a species that has almost no local training data.

## V4.3a Recipe (for when backfill completes)

```
loss:           an_full (pos_weight=2048)
weighting:      effective_cap (cap=1000, no hard cap)
boost:          --no-boost
location:       --use-location-encoding
phylo:          --zero-phylo-input
gate:           --disable-intro-in-gate
land state:     --land-state-mode zero
```

The `--weight-mode effective_cap --effective-cap 1000` flag was implemented this session. It provides the same gradient equalization as hard-cap-1000 but preserves all training data (no rows deleted).
